# Контейнер прошивки

Формат проверен на двух официальных релизах:

| Файл | Версия | Тег |
|---|---|---|
| `M-A8000SGZA-1013.0[EECE].Bin` | 1013.0 | `EECE` |
| `M-A8000SGZA-1014.0[288E].Bin` | 1014.0 | `288E` |

## Размер и раскладка

```
2 097 152 байта = 2 MiB = 32 страницы по 65 536 байт
```

Полезные данные заканчиваются около `0x1FFF89`, дальше `0xFF`.

Каждая страница начинается с настоящей таблицы векторов 8051:

```
+0x0000  02 01 1F   LJMP 0x011F     ; reset
+0x0003  02 20 00   LJMP 0x2000     ; EXT0
+0x000B  02 30 00   LJMP 0x3000     ; Timer0
+0x0013  02 10 00   LJMP 0x1000     ; EXT1
+0x0023  02 32 00   LJMP 0x3200     ; UART
```

Дальше в каждой странице лежит **дублированная библиотека** — одни и те же строки
на одном и том же смещении (`+0x5403`: `Start Program`, `Current Partition(DF)…`).

Страницы используются как банки кода (см. `architecture.md`), а не как отдельные
прошивки: `Partition ONE` / `Partition TWO` в логе — это A/B-схема обновления.

## Строка версии

ASCII, единственное вхождение, смещение `0xD5826`:

```
M-A8000SGZA-1014.0
```

## Контрольная сумма

**Сумма всех 2 097 152 байт по модулю 0x10000.** Она же — 4 hex-символа в имени
файла в квадратных скобках.

Проверка на обоих релизах:

```
1013.0  sum(bytes) & 0xFFFF = 0xEECE   = [EECE]
1014.0  sum(bytes) & 0xFFFF = 0x288E   = [288E]
```

Ни подписи, ни сертификатов в образе не найдено; `SecLib*` — обёртка апдейтера,
которая сравнивает версию и, судя по всему, эту сумму.

> Практический вывод: после любой правки нужно поднять версию и пересчитать тег,
> иначе апдейтер откажется. Это делает `tools/fwtool.py retag`.

## Модели в образе

Одно ПО на всю линейку, выбор по таблице идентификаторов:

```
LS27A70  LS27A80  LS32A70  LS32A80
```

## Что меняется между версиями

Дифф `1013 → 1014`:

- ~203 байта в **каждой** странице — заголовок страницы и строка версии;
- реальный код переписан в двух страницах:
  - страница 5, `0x058E0C–0x05D248` (17 469 байт) — питание, `APPSetPowerOn`,
    autosource, DPMS;
  - страница 6, `0x0666B5–0x068B43` (9 359 байт) — подсветка, аудио-мут,
    валидация обновления.

## Карта страниц (по уникальным строкам)

| Стр. | Содержимое |
|---|---|
| 0 | mode handler: тайминги, `[MODE] #1..#7`, FRC-проверки |
| 1–2 | OSD DP-источник, аудио, PIP, выбор входа |
| 3 | синхронизация, DRR, `SyncState` |
| 4 | auto source switch, таймауты OSD |
| 5 | питание: `APPSetPowerOn`, DPMS, обмен с видеоблоком |
| 6 | детект кабеля, USB-хаб RTS411S, валидация обновления |
| 7 | DPCD, EDID, HPD |
| 11–12, 14, 18, 23, 30 | локализованные строки OSD |
| 13 | источник, refresh rate, H/V-позиция |
| 15 | FRC, HDCP |
| 16, 25 | шрифты/графика OSD |
| 17 | отладочная консоль и `shell` |
| 20 | работа с флешем, USB-обновление |
| 21 | запись EDID |
| 24 | `MailBox_Handler` |
| 31 | драйвер LED |
| 22, 26, 27, 29 | пустые слоты |
